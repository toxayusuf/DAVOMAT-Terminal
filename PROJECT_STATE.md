# DAVOMAT — PROJECT STATE

Версия: v1.3.0
Дата: 2026-09-16

## Зафиксированная архитектура
- Google Apps Script: backend + admin UI + device/enrollment launch links.
- Google Sheets: сотрудники, графики, посещаемость, зарплата, audit.
- Google Drive: контрольные фото.
- GitHub Pages: Face Terminal/PWA.

## Текущий рабочий путь
- Конфигурация устройства передаётся один раз в URL fragment `#cfg=...` и сохраняется в браузере.
- Камера запускается только на top-level `toxayusuf.github.io`, не внутри Apps Script iframe.
- GET/reads: JSONP к Apps Script (`bootstrap`, `enrollment`, `pendingEnrollment`, `requestStatus`).
- Writes: `fetch(..., mode=no-cors, Content-Type=text/plain)` → Apps Script `doPost` → polling `requestStatus` через JSONP.
- Ни iframe bridge, ни `window.opener`, ни ручной ввод URL/device/token не используются.

## Исправление v1.3.0 — производительность
1. Apps Script iframe теперь является только лёгким launcher: в нём не загружается база сотрудников и Face AI.
2. Face AI библиотека Human загружается динамически только на реальной странице камеры.
3. Bootstrap сотрудников/профилей сохраняется в IndexedDB. При повторном запуске UI открывается из локального кэша, а свежие данные подтягиваются в фоне.
4. Human/Face model загружается параллельно с данными и камерой.
5. Service Worker разделён на versioned shell cache и постоянный model cache, поэтому тяжёлые AI-модели не удаляются при каждом обновлении DAVOMAT.
6. После распознавания камера выключается сразу, а экран сразу показывает `ҚАБУЛ ҚИЛИНДИ / Серверга сақланмоқда…`, не заставляя сотрудника смотреть на замороженную камеру.
7. Контрольное фото теперь сохраняется как компактный crop лица до ~420 px, JPEG ~0.52, что существенно уменьшает POST payload и время Drive/Apps Script обработки.
8. `requestStatus` проверяется быстрее: короткие интервалы в начале вместо фиксированных 650 ms.
9. Полный `bootstrap()` больше не вызывается после каждой отметки КЕЛДИ/КЕТДИ.
10. Polling регистрации снижен с 15 до 45 секунд, а очередь и фоновые обновления стартуют с задержкой, чтобы не создавать burst запросов при открытии.
11. Интервал распознавания снижен с ~320 ms до ~240 ms.
12. Экран успешной фиксации возвращается к терминалу примерно через 0.9 сек после подтверждения сервера.

## Диагностика
В меню ⚙ теперь видны замеры:
- База — время bootstrap;
- Face AI — загрузка/warmup модели;
- Камера — время открытия камеры;
- Сақлаш — время серверного сохранения;
- Кэш — использован ли быстрый локальный bootstrap.

## UX правила
- Никакого ручного ввода Apps Script URL, device ID, token или кода сотрудником.
- Камера не работает постоянно.
- Регистрация: админ создаёт задачу → `РЎЙХАТГА ОЛИШ` → камера → 0/6 → 6/6.
- Сотрудник: `КЕЛДИ` / `КЕТДИ` → лицо → сразу `ҚАБУЛ ҚИЛИНДИ` → сервер подтверждает `МУВАФФАҚИЯТЛИ`.
- При offline событие кладётся в локальную очередь и отправляется после восстановления сети.
